# LingoWay

Веб-платформа для изучения английского языка: программы обучения, уроки, база готовых материалов и генерация упражнений по собственному тексту пользователя.

Учебный командный проект по дисциплине «Теория разработки ПО».

## Стек

| Часть | Технологии |
|---|---|
| Бэкенд | Go, Gin, GORM, PostgreSQL, JWT, bcrypt |
| Фронтенд | HTML, CSS, JavaScript, Vite |
| Инфраструктура | Docker, nginx, GitHub Actions |

## Быстрый старт

Сейчас работает запуск бэкенда без Docker.

### Что понадобится

- [Git](https://git-scm.com/)
- [Go](https://go.dev/dl/) версии 1.27 или новее (проверка: `go version`)

### Запуск бэкенда

```bash
git clone https://github.com/TRPO-project/LingoWay.git
cd LingoWay

# 1. Создать файл с настройками
cp .env.example .env

# 2. Запустить сервер
cd backend
go run ./cmd
```

В логе должна появиться строка `server started on :8080`.

### Проверка

Откройте в браузере http://localhost:8080/api/health или выполните:

```bash
curl http://localhost:8080/api/health
```

Ожидаемый ответ: `{"status":"ok"}`. Остановить сервер: `Ctrl+C`.

### Переменные окружения

Файл `.env` не попадает в репозиторий. Шаблон лежит в `.env.example`.

| Переменная | Назначение |
|---|---|
| `PORT` | Порт сервера (по умолчанию 8080) |
| `DATABASE_URL` | Строка подключения к PostgreSQL |
| `JWT_SECRET` | Секрет для подписи JWT-токенов |
| `LLM_API_KEYS` | Ключи LLM API через запятую |

Реальные ключи и пароли не коммитятся.

## Работа с Git

### Ветки

- `main` — стабильная ветка, напрямую в неё не пушим.
- Каждая задача делается в своей ветке от актуального `main`.
- Имя ветки: `тип/номер-задачи-кратко`, только латиница и дефисы.

```
feature/16-auth-api
fix/22-level-calculation
docs/readme
```

Типы: `feature` — новая функциональность, `fix` — исправление, `docs` — документация, `chore` — инфраструктура и мелочи.

```bash
git switch main
git pull
git switch -c feature/16-auth-api
```

### Коммиты

Сообщение в формате `тип(область): что сделано`:

```
feat(backend): add login endpoint
fix(frontend): correct level badge color
docs: update README
```

Один коммит — одна логическая правка.

### Pull request

1. Запушьте ветку и откройте PR в `main`.
2. Заполните описание: что сделано, номер задачи из YouGile, как проверить.
3. Дождитесь зелёного CI.
4. Нужен минимум один review от другого участника. Ревью делаем в течение суток.
5. После одобрения автор PR сливает его и удаляет ветку.

Один PR — одна задача. Большие PR разбиваем на части.

## Структура репозитория

```
LingoWay/
├── backend/
│   ├── cmd/            # точка входа (main.go)
│   └── internal/
│       ├── config/     # загрузка настроек из окружения
│       └── httpapi/    # маршруты и обработчики HTTP
├── docs/
│   └── CONTRACTS.md    # контракты API: запросы и ответы эндпоинтов
├── .github/workflows/  # CI (сборка и проверки при каждом PR)
├── docker-compose.yml  # Docker-окружение (в разработке, задача №13)
├── .env.example        # шаблон переменных окружения
└── README.md
```

## API-контракты

Формат запросов и ответов каждого эндпоинта описан в [`docs/CONTRACTS.md`](docs/CONTRACTS.md). Бэкенд и фронтенд ориентируются на него, чтобы работать параллельно. Меняете эндпоинт — обновите контракт в том же PR.
