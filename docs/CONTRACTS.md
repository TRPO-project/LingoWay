# API-контракты

## Общая проектируемая модель v0.2: пользователи, модули и задания

Модуль содержит несколько заданий и имеет название, тему и сложность A1–C2. У пользователя пока только базовая учётная запись. Прогресс и личный словарь отложены.

- [Общая схема](DATABASE.md) и [SQL](schema.sql): девять таблиц, включая отдельный каталог материалов и избранное.
- [Шаблоны](exercise-templates.json) и [примеры заданий](exercise-examples.json): девять типов из документа эксперта.
- [OpenAPI v0.2](be3/openapi.json): модули, материалы, задания, отдельные ответы и единая очередь `llm_requests`.

Контракт изменён относительно v0.1: числовые ID вместо UUID, `/modules` вместо `/exercise-sets`, `/llm-requests` вместо `/jobs`, отдельная отправка ответа вместо попытки прохождения. `answer_key`, `explanation` до проверки и `password_hash` не выдаются в публичных DTO. У модуля нет публичного автора: служебный `created_by_user_id` не входит в запросы и ответы API. Публичный системный модуль может не иметь создателя; приватный модуль сохраняет внутреннего владельца для контроля доступа.

Реализованы `/api/health` и модуль материалов, описание которого вынесено в отдельный документ. Остальные операции в OpenAPI остаются проектируемыми; поле `x-implemented` отмечает состояние каждой операции.

## Материалы и базовое подключение LLM

Полное описание реализованного модуля, включая запуск, настройки, API, примеры запросов и ответов, ограничения и устройство очереди, находится в едином документе [LLM_MATERIALS.md](LLM_MATERIALS.md).

Текущий этап работает в общем режиме без проверки пользователя. Для маршрутов материалов не нужен `Authorization`; материал и статус обработки читаются по ID. Детали этого режима и технического владельца описаны в том же документе.

## POST /api/login пример
Проектируемый пример входа пользователя; маршрут пока не реализован. Он сохранён для согласования будущей авторизации. Текущий модуль материалов не использует JWT.

**Запрос:**
```json
{
  "email": "user@mail.com",
  "password": "12345"
}
```

**Ответ (успех):**
```json
{
  "token": "eyJhbGci...",
  "user": { "id": 1, "email": "user@mail.com", "name": "Иван", "role": "student", "created_at": "2026-10-15T10:00:00Z" }
}
```

**Ответ (ошибка):**
```json
{
  "error": "Неверный email или пароль"
}
```

## Каталог материалов

Все запросы требуют заголовок `Authorization: Bearer <токен>`. Ответы с ошибками имеют вид
`{"error": {"code": "...", "message": "..."}}`. Исключение: ошибки 401 и 403 от проверки токена пока
возвращают `{"error": "текст"}`, фронтенд должен уметь читать оба формата.

Списки: `{"items": [...], "limit": 20, "offset": 0, "has_more": false}`.
Параметры `limit` (1–100, по умолчанию 20) и `offset` (с 0).

### GET /api/topics
Список тем. Элемент: `{"id": 1, "slug": "it", "name": "IT"}`.

### GET /api/catalog/materials
Список материалов, сначала новые. Полный текст не возвращается.

| Параметр | Значение |
|---|---|
| `topic_id` | один или несколько ID темы: `1` или `1,3` |
| `level` | один или несколько уровней: `B1` или `B1,B2` |
| `favorite` | `true` только избранное, `false` только не избранное |
| `q` | поиск по названию, до 100 символов |
| `limit`, `offset` | постраничная выдача |

Условия объединяются через «и», несколько значений внутри одного параметра через «или».

```json
{
  "items": [
    {
      "id": 2, "topic_id": 1, "level": "B2", "type": "link",
      "title": "Go tour", "description": "Интерактивный тур",
      "url": "https://go.dev/tour/", "is_favorite": false,
      "created_at": "2026-11-12T10:00:00Z"
    }
  ],
  "limit": 20, "offset": 0, "has_more": false
}
```

### GET /api/catalog/materials/{id}
Полный материал: поля списка плюс `body` (текст для `type: "text"`, иначе `null`) и `updated_at`.
`type: "text"` означает «читать на сайте» (поле `body`), `type: "link"` означает «открыть внешнюю ссылку» (поле `url`).

### PUT /api/catalog/materials/{id}/favorite
Добавить в избранное. Ответ 204, повтор ничего не меняет. 404, если материала нет.

### DELETE /api/catalog/materials/{id}/favorite
Убрать из избранного. Ответ 204 (также если материала не было в избранном).

### Ошибки
| Код | Когда |
|---|---|
| 400 `INVALID_QUERY` | неверный параметр фильтра или постраничной выдачи |
| 400 `INVALID_ID` | идентификатор не число |
| 401 | нет или неверный токен |
| 404 `NOT_FOUND` | материала нет |
| 500 `INTERNAL_ERROR` | внутренняя ошибка |

## Каталог: админ-API

Доступно только роли `admin`: без токена 401, с токеном обычного пользователя 403. Роль хранится в токене, поэтому после смены роли нужно войти заново. Формат ошибок и пагинации такой же, как у пользовательского каталога. Поля `is_favorite` здесь нет.

### GET /api/admin/catalog/materials
Список материалов, сначала новые. Параметры `topic_id`, `level`, `q`, `limit`, `offset` как у `GET /api/catalog/materials`. Параметр `favorite` игнорируется. Полный текст (`body`) в списке не возвращается.

### GET /api/admin/catalog/materials/{id}
Полный материал: поля списка плюс `body` и `updated_at`. 404, если материала нет.

### POST /api/admin/catalog/materials
Создать материал. Ответ 201 с созданным материалом.

```json
{
  "topic_id": 1,
  "level": "B1",
  "type": "text",
  "title": "What is an algorithm?",
  "description": "Короткое введение",
  "body": "An algorithm is a set of steps to solve a problem."
}
```

Для `type: "link"` вместо `body` указывается `url`:

```json
{
  "topic_id": 1,
  "level": "B2",
  "type": "link",
  "title": "Go tour",
  "url": "https://go.dev/tour/"
}
```

Правила:
| Поле | Правило |
|---|---|
| `topic_id` | существующая тема |
| `level` | `A1`, `A2`, `B1`, `B2`, `C1`, `C2` |
| `type` | `text` или `link` |
| `title` | 1–200 символов (пробелы по краям обрезаются) |
| `description` | необязательно, до 500 символов; пустая строка превращается в `null` |
| `body` | обязательно для `text` (непустой, до 100 000 символов), не указывается для `link` |
| `url` | обязательно для `link` (только `http://` или `https://`, без пробелов, до 2048 символов), не указывается для `text` |

Неизвестные поля в теле запрещены (400).

### PUT /api/admin/catalog/materials/{id}
Полная замена: передаются все поля, как при создании (в том числе можно сменить `type`). Поля, которые не относятся к типу, очищаются, `description: null` убирает описание. Ответ 200 с обновлённым материалом.

### DELETE /api/admin/catalog/materials/{id}
Удалить материал (отметки избранного у пользователей удаляются вместе с ним). Ответ 204, 404 если материала нет.

### Ошибки
| Код | Когда |
|---|---|
| 400 `INVALID_JSON` | тело не JSON, неизвестное поле, лишние данные после объекта |
| 400 `INVALID_ID` | идентификатор не число |
| 413 `REQUEST_TOO_LARGE` | тело больше 1 МиБ |
| 422 `INVALID_INPUT` | данные не прошли проверку (в `message` указано поле) |
| 422 `TOPIC_NOT_FOUND` | темы с таким `topic_id` нет |
| 404 `NOT_FOUND` | материала нет |

## Пользователи: админ-API

Доступно только роли `admin`: без токена 401, с токеном обычного пользователя 403.
Формат ошибок и пагинации как у каталога. В ответах нет хэша пароля.

Объект пользователя:
```json
{"id": 2, "email": "student@example.com", "name": "Student", "role": "student", "is_blocked": false, "created_at": "2026-11-12T10:00:00Z"}
```

### GET /api/admin/users
Список, сначала новые. Параметры: `role` (`student`, `teacher`, `admin`), `blocked` (`true` или `false`), `q` (поиск по email и имени без учёта регистра, до 100 символов), `limit`, `offset`. Ответ: `{"items": [...], "limit": 20, "offset": 0, "has_more": false}`.

### GET /api/admin/users/{id}
Один пользователь. 404, если нет.

### PATCH /api/admin/users/{id}
Частичное изменение: `{"role": "admin"}` и/или `{"is_blocked": true}`, нужно хотя бы одно поле. Через админку назначаются роли `student` и `admin`. Ответ 200 с обновлённым пользователем.

| Код | Когда |
|---|---|
| 400 `INVALID_JSON` | не JSON, неизвестное поле, лишние данные |
| 400 `INVALID_ID`, `INVALID_QUERY` | неверный идентификатор или параметр |
| 403 `FORBIDDEN` | права администратора были отозваны во время запроса |
| 404 `NOT_FOUND` | пользователя нет |
| 409 `CANNOT_MODIFY_SELF` | администратор меняет свой аккаунт |
| 409 `LAST_ADMIN` | операция оставила бы систему без активного администратора |
| 422 `INVALID_INPUT` | пустое тело, неизвестная или недопустимая роль |

### Блокировка
Заблокированный пользователь получает `403` с кодом `ACCOUNT_BLOCKED` («Аккаунт заблокирован.») при входе (`POST /api/auth/login`, после проверки пароля) и при любом защищённом запросе с ранее выданным токеном. Права проверяются в БД при каждом запросе, поэтому блокировка и смена роли действуют сразу, повторный вход не нужен. Токен удалённого пользователя возвращает 401. Эти ошибки приходят в формате `{"error": {"code", "message"}}`, остальные ошибки `/api/auth/*` пока строкой.

## Темы: админ-API

Доступно только роли `admin` (без токена 401, обычный пользователь 403). Список тем админ получает тем же
`GET /api/topics`, что и все пользователи. Формат ошибок как у остальных админских эндпоинтов.

Объект темы: `{"id": 11, "slug": "english-b2", "name": "English B2"}`.

### POST /api/admin/topics
Создать тему. Ответ 201.

```json
{"slug": "english-b2", "name": "English B2"}
```

`slug`: строчные латинские буквы, цифры и дефисы (`business-english`), до 50 символов. Это стабильный ключ, после создания
не меняется. `name`: 1–100 символов.

### PATCH /api/admin/topics/{id}
Переименовать: `{"name": "English for B2"}`. Ответ 200 с темой. Попытка передать `slug` даёт 422.

### DELETE /api/admin/topics/{id}
Удалить тему. Ответ 204. Если на тему ссылаются материалы или модули, удаление запрещено (409).

| Код | Когда |
|---|---|
| 400 `INVALID_JSON`, `INVALID_ID` | не JSON, неизвестное поле, неверный идентификатор |
| 404 `NOT_FOUND` | темы нет |
| 409 `TOPIC_SLUG_EXISTS` | тема с таким `slug` уже есть |
| 409 `TOPIC_IN_USE` | на тему ссылаются материалы или модули |
| 422 `INVALID_INPUT` | неверные `slug` или `name`, пустое тело, попытка изменить `slug` |

## Выбранные темы пользователя

Требуют `Authorization: Bearer <токен>`. Выбор нужен для программы обучения и фильтра по умолчанию в каталоге.
Пользователь определяется по токену. Формат ошибок как у остальных эндпоинтов.

Ответ обоих запросов:
```json
{
  "items": [
    {"id": 3, "slug": "travel", "name": "Путешествия", "position": 1},
    {"id": 1, "slug": "it", "name": "IT", "position": 2}
  ],
  "max_topics": 5
}
```

`position` задаёт приоритет (1 важнее всего) и всегда идёт подряд с 1. `max_topics` лимит выбора, его нужно брать из ответа, а не хардкодить.

### GET /api/me/topics
Выбранные темы по приоритету. Если пользователь ничего не выбирал, `items` пустой (это не ошибка): фронтенд показывает экран выбора.

### PUT /api/me/topics
Заменить выбор целиком. Порядок `topic_ids` это приоритет: первая тема важнее всех.

```json
{"topic_ids": [3, 1]}
```

Правила: от 1 до 5 тем, повторы игнорируются (остаётся первое вхождение), ID существующих тем. Повторный вызов с теми же данными безопасен. При ошибке прежний выбор не меняется.

| Код | Когда |
|---|---|
| 400 `INVALID_JSON` | не JSON, неизвестное поле, неверные типы |
| 401 | нет токена или пользователь удалён |
| 403 `ACCOUNT_BLOCKED` | аккаунт заблокирован |
| 422 `INVALID_INPUT` | пустой список, больше 5 тем, неположительный ID |
| 422 `TOPIC_NOT_FOUND` | одной из тем нет |

Если администратор удалит тему, она пропадёт из выбора пользователя автоматически, остальные получат `position` без пропусков. Если выбор стал пустым, фронтенд должен снова предложить выбрать темы.
