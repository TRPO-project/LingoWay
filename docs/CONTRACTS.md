# API-контракты

## Общая проектируемая модель v0.2: пользователи, модули и задания

Модуль содержит несколько заданий и имеет название, тему и сложность A1–C2. У пользователя пока только базовая учётная запись. Прогресс и личный словарь отложены.

- [Общая схема](DATABASE.md) и [SQL](schema.sql): девять таблиц, включая отдельный каталог материалов и избранное.
- [Шаблоны](exercise-templates.json) и [примеры заданий](exercise-examples.json): девять типов из документа эксперта.
- [OpenAPI v0.2](be3/openapi.json): модули, материалы, задания, отдельные ответы и единая очередь `llm_requests`.

Контракт изменён относительно v0.1: числовые ID вместо UUID, `/modules` вместо `/exercise-sets`, `/llm-requests` вместо `/jobs`, отдельная отправка ответа вместо попытки прохождения. `answer_key`, `explanation` до проверки и `password_hash` не выдаются в публичных DTO. У модуля нет публичного автора: служебный `created_by_user_id` не входит в запросы и ответы API. Публичный системный модуль может не иметь создателя; приватный модуль сохраняет внутреннего владельца для контроля доступа.

Реализованы `/api/health` и модуль материалов, описание которого вынесено в отдельный документ. Остальные операции в OpenAPI остаются проектируемыми; поле `x-implemented` отмечает состояние каждой операции.

## Материалы и базовое подключение LLM

Полное описание реализованного модуля, включая запуск, настройки, API, примеры запросов и ответов, ограничения и устройство очереди, находится в едином документе [LLM_MATERIALS.md](LLM_MATERIALS.md).

Текущий этап работает в общем режиме без проверки пользователя. Для маршрутов материалов не нужен `Authorization`; материал и статус обработки читаются по ID. Детали этого режима и технического владельца описаны в том же документе.

## POST /api/login пример
Проектируемый пример входа пользователя; маршрут пока не реализован. Он сохранён для согласования будущей авторизации. Текущий модуль материалов не использует JWT.

**Запрос:**
```json
{
  "email": "user@mail.com",
  "password": "12345"
}
```

**Ответ (успех):**
```json
{
  "token": "eyJhbGci...",
  "user": { "id": 1, "email": "user@mail.com", "name": "Иван", "role": "student", "created_at": "2026-10-15T10:00:00Z" }
}
```

**Ответ (ошибка):**
```json
{
  "error": "Неверный email или пароль"
}
```
