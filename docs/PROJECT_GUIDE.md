# Руководство по коду LingoWay

LingoWay предоставляет HTTP API для изучения английского. Пользователь может выбрать интересующие темы, найти готовый учебный материал в каталоге или получить упражнения по собственному тексту. Администратор управляет темами, материалами каталога и учётными записями. Для проверки генерации есть веб-интерфейс на React. Остальные разделы доступны через HTTP API.

## Как запустить проект

1. Из корня проекта создайте локальный файл `.env` из [.env.example](../.env.example), если такого файла ещё нет. В PowerShell для этого служит `Copy-Item .env.example .env`.
2. Укажите `JWT_SECRET` для подписи токенов входа. Для генерации также заполните `LLM_API_KEYS`, `LLM_BASE_URL` и `LLM_MODEL` данными своего провайдера. При пустом списке ключей доступны авторизация, каталог, извлечение текста из файла и чтение сохранённых материалов. Попытка поставить новую задачу генерации вернёт HTTP 503.
3. Выполните `docker compose up -d --build`. Запустятся PostgreSQL 16, сервер Go и веб-интерфейс. Откройте [страницу генерации](http://127.0.0.1:5173). По умолчанию сервер применит миграции при запуске и заполнит пустой справочник десятью темами.
4. Выполните `curl.exe http://localhost:8080/api/health` в PowerShell. Ответ `{"status":"ok"}` подтверждает, что HTTP-сервер принимает запросы. Для проверки доступа к базе зарегистрируйте пользователя и запросите темы с его токеном. Для проверки связи с провайдером пройдите сценарий генерации ниже.

По умолчанию API слушает порт 8080. При изменении `PORT` подставьте свой порт в запросы. Состояние контейнеров показывает `docker compose ps`, журнал приложения — `docker compose logs backend`. Команда `docker compose down` останавливает сервисы и сохраняет данные в томе PostgreSQL. Локальный запуск Go и назначение первого администратора описаны в [README](../README.md).

## Авторизация, каталог и темы

Базовый адрес всех маршрутов в этой таблице — `/api`. Клиент получает JWT при регистрации или входе. Для запросов с проверкой пользователя передавайте его в заголовке `Authorization: Bearer <токен>`. На каждом таком запросе сервер проверяет текущую роль и блокировку в базе. Изменение прав действует со следующего запроса. [Маршруты](../backend/internal/httpapi/router.go) и [проверка учётной записи](../backend/internal/middleware/active_user.go).

| Что нужно сделать | Метод и путь после `/api` | Как работает |
|---|---|---|
| Зарегистрироваться или войти | `POST /auth/register`, `POST /auth/login` | Регистрация принимает имя, email и пароль, вход — email и пароль. Успешный ответ содержит `token` и `user`. |
| Проверить свою учётную запись | `GET /me` | Возвращает ID пользователя и действующую роль. |
| Посмотреть темы и сохранить свой выбор | `GET /topics`, `GET /me/topics`, `PUT /me/topics` | Для сохранения отправьте `{"topic_ids":[1,3]}` со своими ID из справочника. Список из 1–5 различных тем целиком заменяет предыдущий. Порядок сохраняется. |
| Найти материал в каталоге | `GET /catalog/materials`, `GET /catalog/materials/{id}` | Список поддерживает поиск, фильтры по теме, уровню и избранному. Отдельная карточка содержит текст или ссылку. |
| Изменить избранное | `PUT /catalog/materials/{id}/favorite`, `DELETE /catalog/materials/{id}/favorite` | Добавляет или снимает отметку у текущего пользователя. Успешный ответ — 204. |
| Управлять каталогом | `/admin/catalog/materials` и `/admin/catalog/materials/{id}` | Администратор может читать список и карточку (`GET`), добавить (`POST`), заменить (`PUT`) или удалить (`DELETE`) запись. |
| Управлять темами и пользователями | `/admin/topics`, `/admin/topics/{id}`, `/admin/users`, `/admin/users/{id}` | Темы создают, переименовывают и удаляют. Пользователей просматривают списком или по одному, а через `PATCH` меняют роль и блокировку. |

Запрос `GET /admin/dashboard` после префикса `/api` подтверждает доступ к административной группе. Для параметров фильтрации, тел запросов и форматов ошибок используйте [контракты API](CONTRACTS.md).

## От исходного текста до упражнений

**Материал** — исходный текст для модели. **Модуль** — набор упражнений, созданный по этому тексту. Один материал можно использовать для нескольких модулей, например для тренировки грамматики и отдельно для вопросов по прочитанному. Модуль хранит ссылку `material_id`, а каждое упражнение — `module_id`. Эти маршруты работают в общем режиме без входа.

| Шаг | Запрос | Что делать с ответом |
|---|---|---|
| 1. Получить текст из файла, если нужно | `POST /api/materials/extract` | Отправьте TXT, MD или DOCX в поле `file` формы. Сервер вернёт текст для просмотра. Его можно поправить перед сохранением. Готовый текст можно сразу отправить на шаге 2. |
| 2. Создать материал | `POST /api/materials` | Передайте `kind: "text"`, название и текст. ID присвоит сервер. В ответе 202 сохраните адрес из заголовка `Location` и значение `material.id`. |
| 3. Дождаться подготовки | `GET /api/materials/{material_id}` по первому `Location` | Пока статус `pending`, повторяйте чтение с паузой. При `ready` доступны подготовленный текст и уровень CEFR от A1 до C2. При `failed` обработка завершилась ошибкой. |
| 4. Заказать упражнения | `POST /api/materials/{material_id}/modules` | Укажите ID готового материала в пути, а в теле — название модуля, `topic_id`, `difficulty`, `count` и `types`. Тему можно выбрать из `GET /api/topics` после входа. Сохраните адрес модуля из второго `Location`. |
| 5. Дождаться генерации | `GET /api/modules/{module_id}` по второму `Location` | При `generating` повторяйте чтение с паузой. При `ready` переходите к упражнениям. При `failed` опрос закончен. |
| 6. Получить упражнения | `GET /api/modules/{module_id}/exercises` | Возвращает упражнения в порядке прохождения. Для постраничного чтения доступны `limit` и `offset`. При запросе до готовности сервер возвращает 409. |

Например, первый запрос вернул `Location: /api/materials/12`. Читайте этот адрес до `ready`, затем отправьте параметры упражнений в `POST /api/materials/12/modules`. Если второй запрос вернул `Location: /api/modules/7`, читайте этот адрес до `ready`, затем откройте `GET /api/modules/7/exercises`. В карточке модуля 7 останется `material_id: 12`. Числа в примере замените значениями, выданными вашим сервером.

Для двух запросов создания нужен заголовок `Idempotency-Key`. Это UUID, который клиент создаёт для одной конкретной отправки. Если ответ потерялся, повторите тот же запрос с тем же ключом. Сервер вернёт уже созданную сущность. Для следующего самостоятельного создания используйте новый ключ. Внутренний номер задачи `llm_request.id` нужен только для диагностики или совместимости со старыми клиентами. [Готовые примеры запросов и ответов](LLM_MATERIALS.md).

В одном модуле можно запросить от 2 до 30 заданий. Число выбранных типов должно помещаться в число заданий. Сервер распределяет упражнения поровну, а остаток отдаёт первым типам в списке. Доступны четыре лексических типа, три грамматических и два открытых вопроса. Для проверки понимания текста укажите `comprehension_question`, а для аргументированного ответа — `reasoning_question`. Ученик увидит вопрос и цитату из исходного текста. Критерии проверки хранятся отдельно. Формат каждого задания и образец ответа модели приведены в [шаблонах](exercise-templates.json) и [примерах](exercise-examples.json).

### Что происходит на сервере

1. Обработчик HTTP проверяет входные поля. Сервис сохраняет материал или модуль вместе с задачей в очереди PostgreSQL в одной транзакции. Клиент сразу получает адрес ресурса.
2. Один фоновый обработчик подготавливает текст и запрашивает оценку CEFR. Другой получает текст готового материала и запрошенные параметры модуля, затем отправляет их в LLM. Инструкции модели лежат в [каталоге промптов](../backend/internal/generation/prompts).
3. Сервер проверяет ответ модели до публикации. В частности, он сверяет число и типы упражнений, структуру полей, ссылки в ключах ответов и принадлежность цитаты исходному тексту для открытых вопросов. Все упражнения модуля и статус `ready` записываются одной транзакцией. В выдачу для ученика входят задание и его содержимое. Ключ ответа и объяснение остаются в базе.
4. При временном сбое провайдера обработчик повторяет вызов в пределах `LLM_MAX_ATTEMPTS`. Непригодный ответ модели или исчерпанные попытки переводят ресурс в `failed`. Детали настройки, повторов и кодов ошибок описаны в [руководстве по генерации](LLM_MATERIALS.md).

## Как устроены данные

| Таблицы PostgreSQL | Связь и назначение |
|---|---|
| `users`, `topics`, `user_topics` | Учётные записи и справочник тем. В `user_topics` хранятся выбранные пользователем темы и их порядок. |
| `catalog_materials`, `catalog_material_favorites` | Каталог готовых текстов и ссылок. Запись избранного связывает пользователя с карточкой каталога. |
| `materials`, `modules`, `exercises` | Источники для генерации, наборы заданий и сами задания. Тема и сложность задаются на уровне модуля и передаются при чтении упражнений. |
| `llm_requests`, `answers` | Очередь хранит операцию, состояние и ссылки на сущности. Для ответов ученика предусмотрена таблица `answers`. Приём и оценивание таких ответов пока находятся на стадии контракта. |

Например, `GET /api/catalog/materials/12` читает карточку каталога, а `GET /api/materials/12` — источник для генерации. Число 12 в этих адресах относится к разным таблицам. Темы у подсистем общие. Действующую схему определяют [модели](../backend/internal/models), [миграция](../backend/internal/database/migrate.go) и [ограничения PostgreSQL](../backend/internal/database/invariants.sql).

## Где искать код

| Если нужно разобраться в… | С чего начать |
|---|---|
| Создании материала и прохождении упражнений в браузере | Компоненты React и вызовы API находятся в [frontend/src](../frontend/src). Для локальной разработки используется Vite с [прокси на API](../frontend/vite.config.js). В Docker собранные файлы раздаёт nginx. |
| Запуске и настройках | [main.go](../backend/cmd/main.go) открывает БД, вызывает миграцию, запускает HTTP и фоновые обработчики. [config](../backend/internal/config) читает настройки окружения. [database](../backend/internal/database) подключает PostgreSQL, обновляет схему и добавляет стартовые темы. |
| Конкретном запросе | Найдите путь в [router.go](../backend/internal/httpapi/router.go) или в функциях регистрации, которые он вызывает. Обработчики в [httpapi](../backend/internal/httpapi) читают входные данные, вызывают сервис и формируют публичный ответ. |
| Регистрации и правах | [Обработчики входа](../backend/internal/httpapi/auth.go) работают с паролем и учётной записью. [auth](../backend/internal/auth) подписывает и читает JWT. [middleware](../backend/internal/middleware) проверяет токен, блокировку и роль. |
| Каталоге и управлении | [catalog](../backend/internal/catalog) реализует поиск, избранное, выбранные темы и изменение карточек. [admin](../backend/internal/admin) управляет пользователями и справочником тем. |
| Приёме текста и очереди | [materials](../backend/internal/materials) извлекает текст из файлов, проверяет вход, создаёт ресурсы, выдаёт работу фоновым обработчикам и сохраняет результат. |
| Ответах модели | [generation](../backend/internal/generation) отправляет запросы провайдеру, разбирает оценку CEFR и проверяет каждое созданное упражнение. |
| Структуре таблиц | [models/users](../backend/internal/models/users) описывает пользователей и роли, [models/topics](../backend/internal/models/topics) — темы, каталог, модули и упражнения, [models/llm](../backend/internal/models/llm) — исходные материалы, очередь и ответы. |

Из каталога `backend` выполните `go build ./...` для сборки, `go test ./...` для запуска имеющихся тестов и `go vet ./...` для статической проверки. В GitHub Actions для изменений запускаются сборка и статическая проверка. [Настройки CI](../.github/workflows).
